## 1. Generative AI

Generative AI is a class of models that produce new content — text, images,
audio, code — given some input. The defining characteristic is **generative
output**, not just classification or prediction.

```text
User
 ↓
Prompt
 ↓
Generative Model
 ↓
Generated Output
```

**Why it matters for engineers:** traditional software is deterministic;
LLM-based software is probabilistic. The same input can produce different
outputs. Every layer of your application must be designed assuming this.

---

## 2. Large Language Models

An LLM is a neural network trained on a massive corpus of text to predict
the next token given the preceding tokens.

### Training vs Inference

| Stage | What happens | Cost | Frequency |
|-------|--------------|------|-----------|
| **Pre-training** | Model learns language patterns from TB-scale corpora | Millions of $ | Once per model |
| **Instruction tuning** | Model learns to follow instructions | Tens of thousands of $ | Once per model |
| **Inference** | Model generates tokens for one prompt | $ per million tokens | Every request |

You almost never train. You almost always run inference.

### Tokens

A token is the atomic unit the model sees. English averages ~4 characters
per token. `"Hello, world!"` → `["Hello", ",", " world", "!"]` (4 tokens).

| Concept | Meaning |
|---------|---------|
| **Input tokens** | Tokens in your prompt (system + user + history) |
| **Output tokens** | Tokens generated by the model |
| **Token cost** | Provider charges per million tokens, split input/output |
| **Token limit** | Maximum tokens the model can process in one call (context window) |

**Why tokens matter:** cost, latency, and context window are all denominated
in tokens, not characters. Engineers who don't internalize this over-spend.

### Context Window

The total tokens the model can attend to in one call:

```text
System Instructions
        +
Conversation History
        +
Retrieved Documents (RAG)
        +
Tool Results
        +
User Request
        ↓
    LLM (≤ context window)
```

**Failure mode:** stuffing too much into the context window causes:
- Higher cost (you pay for every token, every request).
- Slower inference.
- Lost-in-the-middle effect: models attend less to the middle of the context.
- More hallucinations as the model tries to reconcile noise.

## 3. Prompt Engineering

A prompt is everything sent to the model: system message, user message,
examples, retrieved documents, tool results.

### Anatomy of a Good Prompt

```text
Role:        who the model is
Task:        what to do
Rules:       what to never do
Context:     facts to ground on
Format:      how to structure the output
Examples:    input → output demonstrations
```

### Few-shot prompting

Provide 2–5 input/output examples in the prompt. The model learns the
pattern from them. Use when zero-shot produces inconsistent formatting.

### Structured output

Force the model to return JSON or a typed schema. Use `response_format` or
an output parser:

```json
{
  "category": "VPN",
  "priority": "medium",
  "action": "restart_vpn",
  "requires_ticket": false
}
```

**Why it matters:** downstream code needs a parseable shape, not prose.

## 4. LLM Parameters

| Parameter | What it does | Default |
|-----------|--------------|---------|
| `temperature` | How much randomness in token sampling | 0.7 |
| `top_p` | Cumulative probability cutoff for sampling | 1.0 |
| `max_tokens` | Hard cap on response length | model-specific |
| `stop` | Sequences that halt generation | none |

**Rule of thumb:**
- **0.0** → classification, extraction, code generation (deterministic).
- **0.2–0.5** → structured generation that needs some creativity.
- **0.7–1.0** → creative writing, brainstorming.
- **1.2+** → wild ideation (rarely useful in production).

## 5. LLM APIs

The typical request flow:

```text
Application
 ↓
SDK (openai, langchain-openai, ...)
 ↓
HTTPS
 ↓
Model Provider
 ↓
LLM
 ↓
Response
```

**Production concerns:**
- **API keys:** never hardcode. Use env vars or a secrets manager.
- **Rate limits:** every provider enforces RPM and TPM. Plan for backpressure.
- **Streaming:** most providers support SSE-based streaming. Use it for
  user-facing chat to reduce perceived latency.
- **Timeouts:** set explicit timeouts. Default Python HTTP timeouts are
  far too long for interactive apps.

## 6. Traditional vs LLM Application

| Aspect | Traditional | LLM |
|--------|-----------|-----|
| Logic | Code you wrote | Probabilistic model output |
| Knowledge | Database | Training data + RAG |
| Determinism | Total | Partial (temperature = 0 helps) |
| Failure mode | Exceptions, bugs | Hallucinations, format errors |
| Cost per request | ~free | ~$0.001–$0.10 |
| Latency | ms | 100ms–30s |

The **enterprise** LLM application includes more moving parts:

```text
User
 ↓
API
 ↓
Application
 ├── LLM
 ├── RAG
 ├── Tools
 ├── Memory
 └── Guardrails
 ↓
Response
```

## 7. Common Mistakes

- **Treating the LLM as a database** — it's not deterministic, it's not queryable, and it forgets.
- **Assuming the LLM knows current company info** — it doesn't; you need RAG.
- **Sending unnecessary context** — every token costs money and latency.
- **Not validating model output** — parse, schema-check, retry on parse failure.
- **Hardcoding API keys** — use env vars, secrets managers, or IAM.
- **Ignoring token usage** — log every request's token count and cost.
- **Assuming fluent output means correct output** — confident wrong answers are the worst failure mode.

## 8. Parameters & Model Size

Every weight in the network is a learned number. The total count is the "parameter count" and it's the single biggest factor in capability, cost, and infrastructure footprint.

### Reference table (researched, current as of late 2024)

| Model | Year | Parameters | Notes |
|-------|------|------------|-------|
| GPT-2 | 2019 | 1.5 B | First "good enough" public LLM |
| GPT-3 | 2020 | 175 B | Showed few-shot in-context learning |
| PaLM | 2022 | 540 B | Pathways; Google's flagship at the time |
| Llama 2 | 2023 | 7 / 13 / 70 B | Open-weights; ran on a single GPU |
| Mistral 7B | 2023 | 7 B | Beat Llama 2 13B on most benchmarks |
| Mixtral 8x7B | 2023 | ~46 B (13 B active) | Sparse Mixture-of-Experts |
| Llama 3.1 | 2024 | 8 / 70 / 405 B | 405B competitive with frontier |
| DeepSeek-V3 | 2024 | 671 B (37 B active) | MoE; strong open-weights model |
| GPT-4 | 2023 | ~1.8 T (rumored) | Never officially disclosed by OpenAI |

> Many of these counts come from model cards, technical reports, or industry consensus. Vendor-disclosed sizes are the trustworthy ones.

### Why size matters

- **More parameters → more capacity.** More capacity to memorize facts, follow instructions, reason across domains.
- **More parameters → more compute.** Inference cost scales roughly linearly with active parameters.
- **More parameters → more memory.** A 70B model in FP16 needs ~140 GB just for weights.
- **More parameters → more data.** The Chinchilla scaling law (Hoffmann et al., 2022) showed that optimal training uses roughly **20 tokens per parameter** — a 70B model should train on ~1.4 trillion tokens to be compute-optimal.

### The Chinchilla scaling law

For a fixed compute budget, there is an optimal model size and dataset size. Bigger models trained on less data underperform smaller models trained on more data. **Data matters as much as size.** This is why most frontier labs train on trillions of tokens, not hundreds of billions.

### Mixture of Experts (MoE)

Models like Mixtral 8x7B and DeepSeek-V3 have many parameters but only "activate" a subset per token. Inference cost stays low while total capacity stays high. Trade-off: more complex serving infrastructure (must route tokens to the right expert).

### Sparse vs Dense

| Type | Examples | Inference cost | Capacity |
|------|----------|----------------|----------|
| **Dense** | GPT-4, Llama 3 70B, Claude | High (all params active) | Scales with size |
| **Sparse (MoE)** | Mixtral, DeepSeek-V3 | Lower (fraction active) | Can be much larger |

## 9. Context Window — Engineering the Limits

The **context window** is the maximum number of tokens the model can attend to in one forward pass. System prompt + conversation history + retrieved documents + tool results + new user message all share it.

### Reference table (nominal vs effective)

| Model | Nominal context | Effective in practice |
|-------|-----------------|------------------------|
| GPT-3 (2020) | 2 K | ~2 K |
| GPT-4 (2023) | 8 K / 32 K | ~6 K / ~25 K |
| GPT-4 Turbo (2023) | 128 K | ~64 K |
| Claude 3 / 3.5 (2024) | 200 K | ~150 K |
| Gemini 1.5 Pro (2024) | 1 M (2 M exp.) | ~700 K |

### "Lost in the middle" (Liu et al., 2023)

Models attend strongly to the beginning and end of the context but weakly to the middle. Effective context is almost always smaller than the nominal one. **Practical implication:** put the most important information at the start or end of the prompt, not buried in the middle.

### Cost and latency impact

- **Cost is linear in input tokens.** A 1 M-token context × 1000 requests/day = real money.
- **Latency is worse than linear.** Self-attention is O(n²) in sequence length. Doubling the context roughly quadruples prefill time. Long-context inference is dominated by prefill, not generation.

### Engineering tactics

- **Trim the system prompt.** Every token is sent on every request.
- **Summarize conversation history** when it exceeds a threshold.
- **Compress retrieved documents** — return top-k chunks, not the whole corpus.
- **Cache prefix.** Some providers (Anthropic, OpenAI) let you cache a shared prefix to skip re-processing.
- **Move work to tools, not the prompt.** Instead of stuffing a CSV into the context, expose a tool that returns the relevant rows.

## 10. Prompt Templates — Anatomy & Patterns

A prompt is everything sent to the model. A **prompt template** is a parameterized version you can reuse.

### Anatomy of a high-quality prompt

```text
Role      — who the model is
Task      — what to do
Rules     — what to never do
Context   — facts to ground on
Format    — how to shape output
Examples  — in → out demonstrations
```

### Patterns in chronological order

| Pattern | Reference | When to use |
|---------|-----------|-------------|
| **Zero-shot** | — | Default. Just the task. |
| **Few-shot** | Brown et al., 2020 (GPT-3 paper) | Zero-shot fails to produce consistent format. |
| **Chain-of-Thought (CoT)** | Wei et al., 2022 | Task requires multi-step reasoning (math, logic). |
| **ReAct** | Yao et al., 2022 | The agent needs to reason AND call tools in one loop. |
| **Self-consistency** | Wang et al., 2022 | When CoT is right most of the time but flaky. Sample N, vote. |
| **Tree of Thoughts** | Yao et al., 2023 | Exploration across multiple branches. Expensive. |

### Selection rules

- **Default to zero-shot + structured output.** Fastest, cheapest.
- **Move to few-shot** when zero-shot fails to produce the right format consistently.
- **Reach for CoT** when the task is multi-step (math, multi-hop reasoning, planning).
- **Use ReAct** when the agent must reason + act in the same prompt (tool-calling).
- **Use self-consistency** when CoT is usually right but flaky. Costs more (N samples).
- **Skip Tree of Thoughts** unless exploration is worth 10× the cost.

### Template management

- Store prompts as **versioned files**, not strings in code.
- Track **prompt → version → model → eval score** in your observability system.
- A/B test new prompts against the baseline on a fixed test set.
- A regression in prompt v7 might cost you $10K in misclassified tickets.

## 11. Guardrails — Three Layers

Guardrails are the rules that keep the agent inside its lane. Without them, the agent will eventually do something expensive, dangerous, or embarrassing.

### Layer 1: Input guardrails

Filter the user message **before** it reaches the LLM.

- **PII detection** — Presidio, regex. Redact before sending.
- **Prompt-injection detection** — Rebuff, Lakera. Block known attack patterns.
- **Topic blocklist** — hardcoded list of forbidden subjects ("salary", "SSN", "competitor info").
- **Length / format checks** — reject prompts over N tokens, or malformed JSON.

### Layer 2: Tool guardrails

Filter what the agent **can do** in the outside world.

- **Per-agent tool allowlist** — the Researcher agent cannot call `create_ticket`.
- **Per-user authorization** — only managers can use the access-request tool.
- **Schema validation** — every tool argument is validated against its JSON schema before execution.
- **Rate limit per tool** — Jira allows 100 req/min; cap at 80.

### Layer 3: Output guardrails

Filter the model's output **before** it reaches the user or another system.

- **JSON schema validation** — reject malformed responses; trigger a retry or fall back.
- **PII redaction** — strip any SSN, credit card, email that sneaked into the answer.
- **Toxicity filter** — OpenAI moderation endpoint, Detoxify.
- **Citation presence / accuracy** — for RAG systems, every claim must trace back to a retrieved chunk.

### OWASP LLM Top 10 (2025)

The industry-standard checklist for LLM-application risks. Top entries:

1. **Prompt injection** — attacker subverts instructions via untrusted input.
2. **Sensitive information disclosure** — PII, secrets leak via output or logs.
3. **Supply chain** — poisoned training data, malicious models from upstream.
4. **Unbounded consumption** — DoS via expensive prompts, runaway agent loops.
5. **Improper output handling** — XSS, SQL injection via model output.
6. **Excessive agency** — agent acts beyond its scope or permissions.
7. **System prompt leakage** — internal instructions become public.
8. **Vector and embedding weaknesses** — RAG retrieval returns wrong/confidential data.
9. **Misinformation** — hallucinated facts presented as truth.
10. **Model theft** — proprietary model exfiltrated.

> Treat OWASP LLM Top 10 the same way you treat the OWASP Top 10 for web apps: as a non-negotiable checklist during design review.

### Recommended frameworks

| Layer | Tool |
|-------|------|
| Input PII | Microsoft Presidio |
| Input injection | Rebuff, Lakera |
| Topic control | NVIDIA NeMo Guardrails |
| Output moderation | OpenAI Moderation endpoint, Detoxify |
| Tool authorization | Custom allowlist + per-user authz |
| End-to-end | LangChain Guardrails (if using LangChain) |

### Practical guardrail pattern

```python
def run_agent(user_msg: str) -> str:
    # Input guardrail
    blocked = input_guardrail(user_msg)
    if blocked:
        return blocked

    # Agent loop with tool guardrails
    messages = [...]
    for _ in range(MAX_ITERATIONS):
        resp = client.chat.completions.create(...)
        if not msg.tool_calls:
            return output_guardrail(msg.content)
        for call in msg.tool_calls:
            if not tool_authorized(call.function.name, user):
                continue
            result = execute(call)
        ...
```

Guardrails are not optional. They are the difference between a demo and a product.
