Business Problem

The challenge: 30 business units want to build agents. Each team writes its own. Result: duplicated tools, inconsistent security, no shared eval.
  • Centralized platform — one registry, one gateway, one observability layer.
  • Self-service builder — non-engineers create agents via UI.
  • Standardized tools — MCP servers expose approved tools only.
  • Governance — every agent runs through policy + audit.

LangGraph + Temporal — Why Both?

LangGraph

  • Defines the shape of the workflow
  • Handles state within a single run
  • Supports streaming

Temporal

  • Survives restarts and crashes
  • Schedules long pauses (hours, days)
  • Provides durable retries with backoff
Pattern: LangGraph inside, Temporal outside. Temporal runs the LangGraph workflow as a single activity.

Loading an Agent from the Registry

async def run_agent(agent_id, user_query, user_id):
    # 1. Load agent spec from registry
    spec = await registry.get(agent_id, version="latest")

    # 2. Resolve MCP tools by spec.tools[]
    mcp_clients = [mcp_factory(t) for t in spec["tools"]]

    # 3. Build LangGraph workflow dynamically
    graph = build_graph(spec, mcp_clients)

    # 4. Wrap in Temporal activity for durability
    result = await temporal.execute_activity(
        graph.arun, args=[user_query, user_id],
        start_to_close_timeout=timedelta(
            seconds=spec["limits"]["timeout_seconds"]),
    )
    return result

Functional Requirements

  • Accept a user query via POST /support.
  • Planner decides which sub-tasks are needed.
  • Knowledge Agent retrieves relevant policies via RAG.
  • Ticket Agent can look up or create tickets.
  • Reviewer Agent checks the response for accuracy & safety.
  • Approval Agent blocks any write action until human approves.
  • Stream tokens to client via SSE.
  • Return final answer + citations + tool call log.

Non-functional

  • Per-user budget cap ($0.50 / request).
  • Max 10 iterations.
  • All tool calls traced to Langfuse.
  • PII redaction on input and output.

Starter — Planner Node

class State(TypedDict):
    user_id: str
    query: str
    plan: list[str]
    knowledge: str
    ticket_info: dict
    draft: str
    approved: bool

def planner(s: State) -> State:
    resp = llm.with_structured_output(Plan).invoke([
        {"role": "system", "content": "Decide which sub-tasks are needed."},
        {"role": "user",   "content": s["query"]}
    ])
    s["plan"] = resp.tasks
    return s

def should_run_knowledge(s: State) -> str:
    return "knowledge" if "policy_lookup" in s["plan"] else "ticket"

Common Mistakes — Final List

❌ Mistake 1
Trusting the LLM. Always validate output.
❌ Mistake 2
No iteration cap. Always set max iterations.
❌ Mistake 3
No HITL on writes. Writes = human gate.
❌ Mistake 4
No budget cap. Per-tenant and per-user.
❌ Mistake 5
No observability. Logs + traces + metrics, always.
❌ Mistake 6
Secrets in code. Use a secrets manager.
❌ Mistake 7
No eval. Deploy = run regression suite.
❌ Mistake 8
Too many agents. Start small.
